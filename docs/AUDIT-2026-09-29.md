# DEMO MCP — audit, fixes and production verification (2026-09-29)

Audited surface: `https://demo-mcp.amidevz.workers.dev` (inspector `/`, MCP `/mcp`).
Repository: `Errordevz/demo-mcp`, branch `main` at `a92c8e5` when the audit started.
Audit branch: `arena/01a0ee32-demo-mcp` (single squashed commit on top of `a92c8e5`).

Two things were true at the same time and both matter:

* the reported "HTTP 1042 on `/`, `/health`, `/tools`" was **not** the edge failing
  those routes — they answered 200 on every one of 20 repeats each — but it **was**
  real: Cloudflare returns `error code: 1042` whenever a DEMO tool fetches DEMO's own
  origin, which `http_fetch`, `web_extract` and `url_inspect` all did;
* the deployment was telling three small lies about itself (isolate age, the Browser
  capability, the Jev review threshold) and firing two guaranteed console errors
  (favicon 404s, a private route called anonymously).

Everything below was reproduced before it was changed. Live checks ran from GitHub
Actions runners (the audit sandbox has no HTTPS egress to `workers.dev`) and through
`fetch_page`; offline checks ran in the sandbox against the same commit.

## 2. Investigated and not reproduced (with the limits of the check)

* **HTTP 1042 as an edge response for `/`, `/health`, `/tools`** — 20 requests per path,
  0 non-200, on two independent runs; no `1015`, `1101`, `1102`, `Too many subrequests`
  or `internal error` anywhere in any probe. Limit: all live traffic came from GitHub
  Actions runners and `fetch_page`; the audit sandbox cannot open TLS to `workers.dev`,
  so a client-specific/edge-cache path could not be exercised from the sandbox.
* **`notifications/initialized` → 400** in the first probe: the probe sent a JSON-RPC
  `id`; the repository's own `verify-mcp.mjs` and the later probes get 202. Probe artifact.
* **Argument validation before token check** — `jev_decide` with an invalid `decision`
  reports the schema error before the `decision:use` scope challenge. No data is exposed
  and the tool still refuses without a token: a UX ordering question, reported, not changed.
* **Protected-tool anonymity** — every protected tool refused an anonymous caller with
  `_meta["mcp/www_authenticate"]`; nothing weakened.
* **Cloudflare Access identity** — disabled on this deployment, so the Access JWT path is
  covered by `tests/access-identity.test.ts` (RS256/JWKS, aud/iss/exp/iat/nbf, service
  tokens rejected, subject hashed) rather than live.
* **`sitemap.xml` / `manifest.webmanifest` 404** — a single-page inspector does not need
  either; left alone and reported. `robots.txt` (200) allows crawling; unchanged.
* **Screenshot/video artifact expiry, browser rendering, Workers AI vision/transcription
  with real media, email delivery to a real inbox, Roblox consent and ChatGPT consent**
  — each needs credentials or a human in the loop; covered offline by the existing suites
  (`artifact expiry`, `video-*`, `roblox-*`, `account-*`) and left for live confirmation.

## 5. Security findings and remaining risk

* **SSRF** is now fail-closed in code and in the deployment: scheme allow-list, private
  literals (including obfuscated forms), metadata endpoints, internal suffixes and
  infrastructure ports, DNS-over-HTTPS re-resolution on every hop, and an unverifiable
  hostname is denied. Residual: DNS rebinding between the DoH answer and the fetch is
  not fully excluded (a known limit of check-then-connect on this platform); the resolver
  outage case now costs availability instead of protection — the deliberate trade.
* **Self-fetch** is refused with an explanation instead of 1042. A custom domain (or any
  non-Worker client) is unaffected; the guard only blocks DEMO's own public origin.
* **Auth separation** holds: public tools are `noauth`; only the seven Roblox account
  tools and `jev_decide` are protected (`roblox:read|link|disconnect`, `decision:use`),
  MCP OAuth is ChatGPT-CIMD-only with PKCE S256, single-use 120 s codes, 900 s tokens, no
  refresh tokens, RFC 7009 revocation, per-principal rate limits; DEMO accounts are
  PBKDF2, hashed opaque sessions, enumeration-safe, rate-limited; Roblox consent is a
  separate flow whose tokens never leave the server (AES-GCM-256 at rest).
* **Secrets**: 13 secret bindings on the Worker; no value appears in any route, tool
  result, error or log inspected during the audit; telemetry reports presence booleans only.
* **Open registration** (`accounts.registrationOpen: true`) is the largest remaining
  abuse surface (sign-up spam / resource growth); it is intentional and rate-limited.
* **Unknown-var drift** on future deploys: `--keep-vars` keeps dashboard-only vars alive,
  which is useful but means a var added in the dashboard is invisible to the repository.
  Today there is no drift; a periodic `scripts/audit-mcp-deployment.mjs` run covers it.
* No secret leakage, unsafe dependency, XSS (all dynamic UI values pass `esc()`), or
  unauthenticated data path was found in the areas reviewed.
